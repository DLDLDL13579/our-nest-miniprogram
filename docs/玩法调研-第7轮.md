# 第 7 轮调研：第 8 个玩法的选择（2026-11-03）

| 玩法 | 机制主轴 |

## 三、为什么选「红黑单双大小」

### 1. 它填的是「规则本身在变」这个空白

每轮由**当前玩家临时指定**一条筛选规则（6 选 1），
所有人按这条规则筛掉自己的骰子、再重摇。**规则在游戏过程中不断变化** ——
现有 7 个玩法没有一个是这样的。

### 2. 铁律②命中三条（门槛只需一条）

| 判据 | 是否命中 |
|---|---|
| 真随机且可验证 | ✓ 5 颗骰子逐轮筛减+重摇 |
| 仲裁顺序/计时 | ✓ 6 种规则 × 每人剩余骰子，手算必错 |
| 跨轮持久记录 | ✓ 每人剩几颗、轮到谁，一直变 |
| 秘密信息 | ✗ 全公开 |
| 大量内容库 | ✗ 不需要 |

### 3. 和「比大小」的差异不是"一点点"

| 维度 | 红黑单双大小 | 比大小 |
|---|---|---|
| 目标 | 把骰子**拿光**（拿光的人输） | 比出最大牌型 |
| 过程 | 每轮：喊规则 → 筛掉 → **重摇** → 下一位 | 摇一次 → 选骰重摇 → 比 |
| 规则 | **每轮由玩家临时指定** | 固定不变 |
| 结束 | 有人拿光 | 一轮定胜负 |

**唯一相同的是都用 5 颗骰子。** 过程完全不同：
一个是「规则不断变的淘汰赛」，一个是「一次性比牌」。

### 4. 成本最低

- 素材：**0**（骰子全复用）
- 云函数：1 个 action（喊规则 → 筛骰 → 重摇）
- 前端：1 个界面（6 个规则按钮 + 骰子显示）

## 四、规则细节（本项目口径，必须写死）

### 六种规则

| 名字 | 筛掉什么 | 说明 |
|---|---|---|
| 红的拿掉 | 红色的骰子 | 骰子没有颜色！**本项目需要给骰子上色** |
| 黑的拿掉 | 黑色的骰子 | 同上 |
| 大的拿掉 | 4、5、6 | |
| 小的拿掉 | 1、2、3 | |
| 单数拿掉 | 1、3、5 | |
| 双数拿掉 | 2、4、6 | |

⚠️ **发现一个真问题**：现有骰子是黑白的（SDF 渲染的象牙白 + 深色点），
**没有红色骰子**。而「红黑单双大小」的前两条规则完全依赖颜色。

三个选择：
1. 渲染一套红色骰子图（成本：改 `render-dice.py` 重跑，约 6 张图）
2. 去掉红黑两条规则，只留四条（大/小/单/双）—— 但玩法名就不能叫「红黑单双大小」
3. 用别的二元属性替代（比如「点数大/小」已有，重复）

**本项目选 1**：红黑是这个玩法最直观的两条规则，去掉就少一半变化。
红色骰子可以用现有骰子的**调色**实现（SDF 渲染器改 base color 即可，几何不变）。

### 输赢与喝酒

- 骰子拿光的人是**输家**，喝 1 杯
- 若同一轮多人同时拿光 → 都喝
- 若某条规则筛完后**所有人都是 0 颗** → 那一轮作废，重喊（避免死锁）

### 边界（必须写死，否则会吵）

1. **第一次喊规则时所有人都是 5 颗**（还没筛过）
2. **筛完必须重摇**，否则下一轮规则就没意义了
3. **每轮只能喊一次规则**，喊的人就是当前轮次玩家，喊完轮到下一位
4. 规则由**喊的人**指定，不是投票 —— 这是"我说了算"的权力轮转
