# 云端 24 个 action 的权限一览（2026-11-03 审计）

> **为什么要有这张表**：上一轮删掉了 `probeWrite` —— 一个能**写任意字段到任意房间**、
> 却**没有任何属主校验**的测试后门。它是 2026-10-29 定位 bug 时的工具，
> 诊断完就忘了删。
>
> 这类东西的检查方式很朴素：**把所有 `action === 'xxx'` 列出来，
> 逐个问「这个是给玩家的，还是给我自己的」**。

## 一、有房主校验的（10 个）

只有房主能调，否则返回「只有房主能 xxx」：

`start` `again` `game` `deck` `lock` `nudge` `rename` `spin` `uwSay` `uwVote` `cardDel`

## 二、有 openid / loadRoom 校验的（11 个）

玩家能调，但必须先证明"你在这个房间里"：

`bid` `open` `pi` `roll` `reroll` `pkAct` `card` `status` `join` `leave` `ping`

## 三、无校验的（3 个，都有正当理由）

| action | 为什么可以无校验 |
|---|---|
| `create` | 建房时还没有房间，无从校验 |
| `ping` | 纯预热，不读写任何数据 |
| `selftest` | 「我的 → 复制诊断信息」用的数据库自检 |

### ⚠️ `selftest` 的特殊性

它会 **创建 → 读 → 写 → 删除** 一个 `probe: true` 的临时文档，
用来确认数据库读写正常。**自清理、不碰真实数据**，但：

1. **任何人可以调**（不检查是谁）
2. **每次调用产生 2 次写操作**（add + remove）

**风险等级：低**（不破坏数据、成本极低），所以保留 ——
它是用户求助时唯一的"数据库是否健康"证据。

**如果以后被刷**，加一个"每 openid 60 秒一次"的节流即可。

## 四、加新 action 时的检查清单

1. **是给玩家的，还是给我自己调试的？**
   调试用的**要么加环境开关，要么用完就删**（`probeWrite` 的教训）。
2. **改写类**：有没有 `loadRoom` + `OPENID` 证明"我在这个房间"？
3. **房主专属类**：有没有 `hostOpenid === OPENID`？
4. **读数据类**：返回的字段里**有没有别人的秘密**？
   （骰子、卧底身份都必须在服务端丢掉，不能让前端藏）
5. **错误 msg 是给人看的吗**？（57 条里只有「缺少探针房间」不是人话 ——
   而它恰好是唯一一个不该存在的 action）

## 五、三个「秘密信息」的边界（2026-11-03 逐个验证）

酒桌游戏的命门全在这三样上：**别人不能知道我的信息**。
而它们**错了不会有任何可见现象** —— 界面照常、功能照常，
只有懂行的玩家抓个包才会发现。**而那个人多半不会告诉你。**

| 秘密 | 该藏的字段 | 现在的做法 | 结论 |
|---|---|---|---|
| **大话骰·骰子** | `players[].dice` | `dice: p.openid === openid ? p.dice : undefined` | ✓ 别人的给 undefined |
| | `players[].diceCount` | 单独给（界面要显示"还差谁没摇"）| ✓ |
| | 结算 `allDice` | 只在 `phase: 'over', lastResult` 里 | ✓ |
| **卧底·身份** | `players[].uwRole` | **完全不下发**（连自己的也不给）| ✓ 双盲 |
| | `players[].uwWord` | 同上 | ✓ |
| | 结算揭晓 | `lastResult.civilianWord` / `spyWord` | ✓ 局后 |
| **金花·牌** | `players[].cards` | **完全不下发** | ✓ |
| | `poker.myKnown` | 只给自己的第一张 | ✓ |
| | `poker.publicCard` | 给所有人（它本来就是公开的）| ✓ |

### 对应的断言

  · `shape()` 的 players 映射里不许有 `uwRole` / `uwWord`（test-contract）
  · 骰子必须按 `isMe` 过滤、`allDice` 只在结算路径（test-contract）

### 为什么这类断言要锚到"那一行"

`uwRole` 在云函数里出现 20 多次（判胜负、选人、结算），
`dice` 出现几十次 —— **只有 `shape()` 里那一行是"边界"**。

整文件扫会误报，所以断言必须**先定位到 `shape()` 里的映射块**再查。

> **判据：安全断言要盯「不该出现的字段」，不是「该出现的字段」。**
> 正面清单漏一项只是功能少；**负面清单漏一项，而页面看起来一模一样。**
