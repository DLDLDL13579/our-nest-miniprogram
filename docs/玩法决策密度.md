# 五个玩法的「决策密度」

> **为什么记这个**：用户说「重点在优化不在新加游戏」。
> 而"优化一个玩法"最先要回答的是：**它有没有足够多的"要想一下"的时刻？**
> 太少 = 无聊（点一下就看结果），太多 = 负担（酒桌上没人愿意算 30 秒）。

## 一、各有多少个决策点

| 玩法 | 模板按钮 | **实质决策** | 决策类型 |
|---|---|---|---|
| 大话骰 | 4 | **3** | 叫多少 / 要不要开 / 要不要劈 |
| 梦幻金花 | 3 | **3** | 比谁 / 换不换（有代价）/ 弃不弃 |
| 比大小 | 3 | **2** | 摇一次的时机 / 重摇哪颗（≤3 次） |
| 谁是卧底 | 3 | **2** | 说什么（口头）/ 投谁 |
| 命运转盘 | 5 | **1** | 转 |

"模板按钮"和"实质决策"不同：**「催一下」是社交功能、「离开房间」是退路，都不是决策**。

## 二、为什么这样是合理的

**大话骰和金花是"主菜"**（3 个决策，且互相牵连）：
- 大话骰：叫的数量/点数 → 决定下家压力 → 决定该不该开
- 金花：换牌的代价（1 杯/半杯）→ 值不值 → 比谁（信息不对称）

**比大小和卧底是"节奏型"**（2 个决策，间隔短）：
- 比大小每局固定 5 颗骰子，决策在"要不要花次数重摇"
- 卧底每轮只有投票一次手机操作（描述是口头的）—— 这符合"手机是道具"的铁律

**转盘只有 1 个决策，但这不是缺陷**：
它的价值不在"选择"，在**内容库**（200 条题卡、240 个卧底词这类）。
转盘是**暖场/惩罚**用的，点一下就出结果恰恰是它该有的样子。

⚠️ **不要为了"决策数好看"给转盘加选项** ——
那就变成了另一个玩法，而且会让"转一下"这个动作变慢。

## 三、决策点的可达性（比数量更重要）

**数量够了但用户点不到，等于没有。** 本项目踩过一次：
金花的「换牌」方法、服务端 action、代价计算、二次确认弹窗全齐，
**模板里从来没有按钮调用它** —— 规则说明写着"换底牌喝一杯"，界面上找不到入口。

现在三个金花按钮都在 `room.myTurn && !poker.folded` 之下：
**轮到你、且还没弃牌时才能看到** ✓

有断言覆盖：`test-contract` ③b（js 里定义的方法必须在模板的 bind/catch 里出现）。

## 四、怎么用这份表

**优化某个玩法时先问**：
1. 它的决策点有几个？和它的定位匹配吗？
2. 每个决策**真的影响结果**吗（还是纯装饰）？
3. 每个决策的按钮**在那个时刻可见吗**？

**加玩法时先问**：它的决策点在哪？如果只有 1 个，那它的价值必须在**内容**或**气氛**上。

## 五、强制等待的时长（2026-11-03 实测）

**"强制等待"= 从动作开始到玩家能再次操作之间，不可避免的动画时长。**

| 玩法 | 强制等待 | 构成 |
|---|---|---|
| 大话骰 | **1.8 秒** | 摇盅 1.05 + 扣盅 0.38 + 开盅 0.34 |
| 比大小 | **2.6 秒** | 摇盅 1.05 + 扣盅 0.38 + 骰子落桌 0.75 + 最后一颗落定 0.42 |
| 金花 | **0.7 秒** | 翻牌 0.26 + 摊牌 0.42 |

### 为什么这个区间是对的

**1~3 秒是"仪式感"的合理区间**：

  · **低于 0.5 秒** → 没有"发生了一件事"的感觉，像点了个按钮就读出结果
  · **高于 3 秒** → 等的人开始摸手机（酒桌上尤其，大家本来就分心）

三个玩法**故意不一样长**：

  · **比大小最长（2.6 秒）** —— 它一局只有这一次动作，慢一点是"发牌的感觉"
  · **大话骰居中（1.8 秒）** —— 但一局要叫十几次，所以每次的开盅必须快点
  · **金花最短（0.7 秒）** —— 它的节奏是"轮流决策"，不是"揭晓"

### ⚠️ 这个数字是"设计值"，不是"体验值"

`animMs` 是**我定的动画时长**，而"体感 1.8 秒"要真机跑才知道 ——
其中包括 **setData 的跨线程延迟**（一次 setData 约 16~50ms）、
GPU 合成、以及低端机的掉帧。

**所以在低端机上，它只会更长，不会更短。** 而"多长算太长"只有玩的人知道。
