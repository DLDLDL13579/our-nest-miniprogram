## 二、试收得出的判据（比答案本身值钱）

### 好题必须落在「听说过，但记不准」的区间

这是本轮最重要的发现。判据加一条（原来的四问不够）：

| 类型 | 例子 | 后果 |
|---|---|---|
| **人人皆知** | 一年 365 天 / 扑克 54 张 / 棋盘 64 格 | 所有人答案一样，**押注变成抛硬币** |
| **听说过但记不准** | 长城多长 / 珠峰多高 / 日地光行多久 | 有人猜 5000、有人猜 2 万 —— **这才有得押** |
| **太冷门** | 某年某次普查的精确数 | 全靠蒙，和抛硬币没区别 |

> **判据⑤：答案必须落在"听说过但记不准"的区间。**
> 太常识 = 无张力；太冷门 = 全靠蒙。这两种都让玩法退化成抛硬币。

### 其余四条（沿用第 5 轮）

1. 答案**永远不变**（不收人口 / 价格 / 纪录 / 在任人数）
2. 一句话问清，不需要图表
3. 数量级合理
4. 有**唯一权威出处**，且措辞要准（"推荐"不能写成"标准"）

### 量级要分层，一局里才有大有小

- 十位级：成人骨头 206、马拉松 42.195
- 千位级：珠峰 8848.86、长城 8851.8、赤道 40075
- 十万级：光速 299792.458

## 三、成本对比（决定做不做）

| 项 | 内容 |
|---|---|
| 题库 | 收 50 道 → 需试收约 100 条，每条核出处 |
| 云函数 | 写答案 / 排序公开 / 秘密下注 / 不超过判定 / 筹码账本 / 全押 = 6 步 |
| 前端 | 数字输入 / 排序列表 / 下注 / 结算榜 = 4 个界面态 |
| 测试 | 规则穷举 + 并发下注 + 掉线兜底，估 15+ 项断言 |

对比现有最复杂的金花（3 张牌 + 换牌代价 + 比牌 + A23 特例 = 4 步）：
**状态机步数更多，但没有组合数学，单步更简单。**

---

## 四、必须写死的歧义（不写一定会吵）

1. **两枚标记押同一格** → 算 100+200 一起结算，还是各算各的？（本项目：各算各的）
2. **平手** → 官方规则是"最年轻者赢"。本项目要不要跟？（建议跟，且写进规则页）
3. **全押上限** → 第 7 题能押上全部筹码，有没有上限？
4. **"不超过"的判定** → 超过正确答案的答案**全部作废**，不是绝对差最小。
   这一条最容易吵，必须在规则页用一句话说清。
5. **答案相同的格子** → 该格所有人都是"猜中者"。

---

## 五、结论

**建议做**，但下一轮要先完成题库（50 道），再动代码。
理由：判据最硬的是"大量内容库"，而它是唯一一个**做得再好也补不回来**的部分 ——
代码能返工，题库不行（质量差的题会让整个玩法失去意义）。

本轮不写代码，只沉淀判据和试收结果 —— 因为**先用 12 条试收把判据验出来，
比写完 6 步状态机再发现题库收不出来要便宜得多。**
