# 已经查过、确认没问题的（2026-11-03）

> **为什么记这个**：开发到现在，很多"看起来该有问题"的地方其实是对的。
> 而**不记下来，下次还会从零查一遍** —— 或者更糟：凭印象"觉得那里有问题"，
> 跑去改一个正确的地方。
>
> 每条都注明**怎么查的**，方便以后复现。

## 一、随机性（酒桌游戏的可信度全押在这上面）

| 项 | 结论 | 怎么查的 |
|---|---|---|
| 金花发牌 | ✓ 洗牌后依次取，不会重复 | 读 `dealDream` |
| 洗牌算法 | ✓ 标准 Fisher-Yates（无偏） | 读 `shuffle` + 实测 6000 次分布偏差 3.1% |
| 卧底选人 | ✓ 同样 Fisher-Yates | 读 `undercover` 分支 |
| 骰子 | ✓ `1 + floor(random()*6)` | 读代码 |
| 转盘扇区 | ✓ 权重总和 100 | 4 个权重相加 |
| 抽题 | ⚠️ 曾纯随机（一局平均重复 1.65 次）→ 已加 `usedCards` 去重 | 模拟 2000 次 |

## 二、状态与并发

| 项 | 结论 | 怎么查的 |
|---|---|---|
| 加人（原子性） | ✓ 只用一个 `_.push`，无读-改-写窗口 | grep 加人点，确认只有 1 处 |
| 人数上限 | ✓ 只在云端算（`gameCap`），前端不重复 | grep |
| 重置游戏状态 | ✓ 清 phase/bid/lastResult/turn/spin + 每人 dice/cards/uw* | 读 `again` 分支 |
| 裸 `setTimeout` | ✓ 0 处（全部进 `_cupTimers` 等清单） | 正则扫未被 push 包裹的 |
| 轮询并发 | ✓ 上一次没回来就跳过 | 读 `pollTick` |
| 连点 | 逐个判：叫骰/再来一局**要防**；换牌/摇骰**不用**（幂等） | 分析每个操作的语义 |

## 六、还没核验的（需要真机）

| 项 | 为什么 |
|---|---|
| 实际声音好不好听 | **我写不出"好听"的判据** —— 频谱/响度/穿透力都只是必要条件 |
