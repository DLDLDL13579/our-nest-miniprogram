## 一点五、断言抽查：核心的那几条是真的吗

**273 项断言全绿**只说明"它们都通过了"，不说明"它们真的在测东西"——
这个项目里栽过好几次"改坏了断言照样通过"。

所以用 `scripts/verify-assert.py`（改坏 → 跑测试 → 自动恢复）抽查了最要命的五条：

| 断言 | 怎么改坏的 | 结果 |
|---|---|---|
| **别人的骰子不能泄露** | `dice: p.openid === openid ? ...` 改成谁都给 | ✓ 报了 |
| **只能往上叫** | `okHigher = n > cur.n \|\| ...` 改成恒真 | ✓ 报了 |
| **单人卧底的限制** | `soloMin` 回退成 1（一个人也能开卧底） | ✓ 报了 |
| **锁房能拦住新人** | `if (room.locked && !alreadyIn)` 改成恒假 | ✓ 报了 |
| **催一下的限流** | 15 秒间隔改成不拦 | ✓ 报了 |

五条全部**改坏了就报**，不是假绿。

第二轮又抽查了四条：

| 断言 | 怎么改坏的 | 结果 |
|---|---|---|
| **回合 45 秒超时自动开骰** | 超时条件改成恒假 | ✓ 报了 |
| **摇过不能再摇** | 拦重复摇的 `if` 改成恒假 | ✓ 报了 |
| **重开一局清干净** | `again` 里删掉 `uwLastOut: null` | ✓ 报了 |
| **卧底连自己都不知道身份** | `myRole` 去掉"出局后才给"的判断 | ✓ 报了 |

⚠️ 其中"回合超时"第一次**没验出来**（改坏了照样通过）——
   因为我跑的是 `test-flows.js`，而那条测试其实在 `test-room.js`。
   **反向验证除了选对改动点，还要选对测试文件。**

第三轮补两条（跨领域）：

| 断言 | 怎么改坏的 | 结果 |
|---|---|---|
| **音效比动画晚 30ms** | `sfxDelay = impact + 30` 改成 `impact` | ✓ 报了 |
| **房主走了要转移** | `hostOpenid = players[0].openid` 改成不转移 | ✓ 报了 |

⚠️ "音画时序"第一次也**没验出来**，但这次不是测试选错，而是**层级不同**：
   `test-feedback.js` 测的是 `timeline()` 返回的**数据表**，
   而我改的是 `fire()` 里的**运行时调度**。静态断言看不到运行时行为 ——
   这是静态测试的固有盲区，不是断言废。

第四轮把工具扩到能跑 Python 测试（`.py` 用 python3，其余 node），
补上了**音频响度层级**：

| 断言 | 怎么改坏的 | 结果 |
|---|---|---|
| **扣盅要是全场最响的一下** | `cup-slam` 目标 RMS 从 1010 改成 400 | ✓ 报了 |

**一共抽查 12 条核心断言，全部"改坏了就报"。**

三次"没验出来"的归因各不相同，值得记：
① 选错测试文件（回合超时在 test-room 而我跑了 test-flows）
② 有两道防线（人数上限，要全拆）
③ 测的层级不同（数据表 vs 运行时调度）

第四次（前端 `data-l`）是**工具本身的缺陷**：
`data-l="{{item}}"` 在文件里出现 **2 次** —— 第一次在**注释**里，
我的工具只替换第一处，改的是注释，真正的按钮没动，所以断言"照样通过"。
工具当时是**警告**了一句，但输出被我 `tail` 掉了。

→ 已改成**出现多次就拒绝继续**（不靠人注意警告）。
→ 换成唯一片段重验：✓ 报了。

**"断言没报"不等于"断言废了" —— 先归因，再下结论。**

## 一点六、可诊断性：「我的」页成了诊断面板

真机出了问题，我原来只能靠用户描述（"操作失败""有点卡"）。
现在「我的」页有三样东西可以**一键复制**：

| 入口 | 内容 | 什么时候用 |
|---|---|---|
| 错误记录 | 时间 / 云函数 / action / 原始错误串（最近 20 条） | 报"操作失败" |
| 诊断信息 | 版本 / 机型 / 系统 / 微信 / 基础库 / 屏幕 / 网络 / **上次启动耗时** | 报"卡""显示不对" |
| 内存警告 | `wx.onMemoryWarning` 触发时也进错误日志 | 报"玩久了变卡" |

**启动耗时**是这一组里最有用的：`onLaunch → onReady` 的差值，
反映"主包大小 + 首屏渲染"的变化（不是用户感知的全部，前面还有小程序启动阶段）。
拆分包前后这个数字应该明显不同 —— 而在此之前，"首屏多快"一直是个我答不上来的问题。

隐私口径：错误日志**只记技术信息**，不记昵称、房间号、词/题。

## 二、没有验证的（只有真机能回答）

| 项 | 为什么验不了 | 怎么验 |
|---|---|---|
| **首屏耗时** | 渲染器和开发版都不代表真机 | 手机上数秒数 |
| **base64 字体是否加载** | `wx.loadFontFace` 对 data URI 的支持依赖基础库 | 看数字是不是窄体 |
| **分包音频能否播放** | 路径合规但没在真机跑过 | 听摇盅/扣盅/翻牌 |
| **动画是否掉帧** | 渲染器不模拟 GPU | 玩一局看卡不卡 |
| **交互是否顺手** | 需要真实手指 | 玩完一局告诉我哪里别扭 |
| **内容会不会冷场** | 需要真实酒桌 | 用一晚上看哪条题没人接 |

> ⚠️ 这六项里，**前两项如果失败，我今天做的两个优化就是白做**（分包音效、字体）。

## 三、已修的真问题（这两天）

按发现顺序，只列**会让人不想再玩**的那一类：

| 问题 | 后果 |
|---|---|
| 单人开卧底卡死在投票页 | 一个人试玩直接卡住 |
| 摇完还能再摇（骰子被重摇） | 结果不可信 |
| 重开一局卧底状态残留 | 第二局起点就是脏的 |
| 云函数超时显示英文 `fail timeout` | 用户只能反馈"操作失败" |
| 进房卡住只说"马上就好" | 分不清在等还是死了 |
| 房主锁房后自己人也进不来 | （已避免：房内重进不受影响） |
| 题库 3 条会得罪人/冷场的题 | 一桌人尴尬一次 |
| 大话骰规则没说"输了喝几杯" | 桌上第一个问题答不上 |
| 大话骰规则没说"什么叫更大" | 那句"这个能叫吗"每次开局都要问 |
| 卧底规则没说平票怎么办 | 投票类必然撞上 |
| `sfx.init` 从未导出（预加载从没生效） | 第一下音效慢半拍 |
| 版本号停在 3.9.78 而实际 3.10.x | 用户报问题时对不上 |

## 四、明确放弃的（不是漏，是想过之后不做）

| 项 | 为什么不选 |
|---|---|
| 今晚战况持久化（"你 3 杯 / 老王 1 杯"） | 三个结算点的 lastResult 结构各异，改五处且漏一处不报错 |
| 分享解锁牌组 | 要建分享闭环，收益不确定 |
| 稀有彩蛋（1/8 概率） | 要改转盘数据结构，会牵动前后端一致断言 |
| 背景音乐 | 酒桌上大家说话，有旋律的曲子会抢。改做极低音量环境底噪 |
| WebP 图片 | 小程序对 WebP 的支持依赖基础库，不显示就是整张图消失 |
