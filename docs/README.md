# docs 索引

> 这个目录是给**人**看的。给 AI 看的在根目录 `AGENTS.md`，给机器跑的在 `scripts/`。

---

## 如果你想……

### 「我刚拿到这个项目，先看什么」

1. 根目录 **`README.md`** —— 项目是什么、怎么跑起来、怎么部署
2. **`项目体检报告.md`** —— 哪些确认可用、哪些没验证、哪些明确放弃
3. **`两分钟自测.md`** —— 5 步上手，每步一句"该看到什么"

### 「我遇到问题了」

| 情况 | 看哪 |
|---|---|
| 小程序报错 / 卡住 | 先在「我的」页复制诊断信息，再对照 `项目体检报告.md` 的"没验证的"一节 |
| 某个界面看着不对 | `视觉检查记录.md` —— 先确认是不是已知的"渲染器假象" |
| 想确认某功能是否真的可用 | `项目体检报告.md` 的"确认可用"表格，每条都注明了**怎么验的** |

### 「我想验收 / 提测」

- **`真机验收清单.md`** —— 36 项，按玩法分组，哪条不对就在编号上写一句
- **`两分钟自测.md`** —— 懒人版，5 步

### 「我想知道这几天改了什么」

- **`这两天的改动.md`** —— 按主题分组（不是流水账），含"没变的"一节

### 「素材是哪来的，能商用吗」

- **`素材来源与许可.md`** —— 逐个列出来源与许可（Kenney / Poly Haven 全 CC0，
  Bebas Neue 是 OFL，骰子和骰盅是自渲染的）

### 「我想了解设计取舍」

- **`research/`** —— 调研记录：竞品对比、音频素材、游戏手感规格
- 根目录 **`AGENTS.md`** —— 所有"为什么这么做"的判据和踩过的坑（很长，按需搜）

## 目录内容一览

| 文件 | 一句话 |
|---|---|
| `两分钟自测.md` | 5 步上手，降低反馈门槛 |
| `真机验收清单.md` | 36 项按玩法分组的验收项 |
| `项目体检报告.md` | 确认可用 / 未验证 / 已修 / 已放弃 |
| `这两天的改动.md` | 按主题整理的改动清单 |
| `视觉检查记录.md` | 区分"真问题""设计如此""渲染器假象" |
| `素材来源与许可.md` | 每个素材的来源与许可 |
| `research/` | 调研记录（竞品、音频、手感规格） |
| `archive/` | 情侣版时代的文档 —— **不是规格**，只是历史 |
