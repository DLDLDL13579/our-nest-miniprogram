## 第三阶段（第 100 轮之后）：把"也许没在跑"的东西逐个验一遍

这个阶段产品改动变少了，做的是**确认**——因为很多机制**代码看起来有、实际可能没在跑**，
而且失效时**不报错**，只是悄悄让体验变差。

### 七条"机制是否真的在跑"的断言

| 验什么 | 怎么验 | 失效的后果 |
|---|---|---|
| 音效抖动 | 同一次 play 调 20 遍，看 `playbackRate` 取值数 | 一局里同一声音完全一样＝打点机感 |
| 音效池化 | 密集音效连播 3 次，看是否建出 3 个实例 | 摇盅 22ms 一次的撞击互相掐断 |
| 轮询去重 | 给两份快照看返回值 | 每 1.5 秒重绘一次，手机发烫 |
| 首次引导 | 模拟进大厅 → 离开 → 点卡 → 再进 | 每次都弹（骚扰）或永远不弹 |
| 最近排序 | 玩三个 → 再玩一个 → 看顺序 | 常玩的玩法排不上来 |
| 我的页刷新 | 玩完回来再 onShow | 显示"今晚 0 局" |
| toast 时长 | 按 150ms/字算 | "点了没反应"其实是提示已消失 |

### 抽样的方法也验过了

`scripts/verify-assert.py` 把"改坏 → 跑测试 → **finally 恢复**"做成一次原子操作。
它解决了我犯过**三次**的错：用 `git checkout` 恢复会冲掉未提交的修改。

一共抽查 **12 条**核心断言，全部"改坏了就报"。而**四次"改坏了没报"**的原因全不一样：

| 现象 | 真实原因 |
|---|---|
| 人数上限拆一处不报 | 有两道防线，要全拆 |
| 回合超时改坏不报 | 选错测试文件 |
| 音效延迟改坏不报 | 测的层级不同（数据表 vs 运行时） |
| `data-l` 改坏不报 | 片段不唯一（改到了注释） |

**没有一次是断言失效** —— 直接按"废了"处理会去改四条正确的断言。

### 顺手修掉的两个真 bug

- **「我的」页的数字停在首次进入时**（今晚几局 / 错误条数）——
  它们放在 data 的 IIFE 里，等于只在第一次进 tab 时算一遍。
- **首次引导三个玩法都标「上次」** —— 改完当天就回头看，发现文案不通顺。

### 小的产品改进

- 大厅「上次玩的」从记 1 个改成 **3 个**（一桌人常玩的是两三个）
- 「我的」页的玩法名**能点了直接开桌**（原来只能看）
- 结算页底部显示「**今晚第 N 局**」
- 可点面积提到 **44pt**（"看规则""离开房间"原来只有 32pt）
- 退房卡住 5 秒后换一句话（"马上就好"到底多久？）

## 第四阶段：真机反馈驱动的修复（2026-10-29）

你给了四条反馈，每条都指向**同一个病根**：**出错的时候没把信息交出来**。

| 你说的 | 根因 | 修法 |
|---|---|---|
| 「卡在正在进入房间」 | 3.10.26 我给点卡建房加了全屏遮罩，而 `doCreate` **从来没关闭** | 补 `setLoading(false)` + 15 秒兜底强制关 |
| 「所有游戏开不了房间」 | `safe()` 对**内容检查服务自身失败**也返回 `pass:false`，建房被整个拦死（部署后 openapi 权限需要几次才绑定） | **分层降级**：昵称放行、自定义题卡仍拦 |
| 「声音有延迟」 | 全站 34 个音效**只预加载了 6 个**，其余 28 个首次播放才加载 | 扩到 13 个（一局开头必响的那些） |
| 「复制不了」 | `setClipboardData` **没有 fail 回调**，失败时一片安静 | 补 fail + **错误原文直接印在页面上** |

### 由此补的断言

| 断言 | 管什么 |
|---|---|
| ④d | 拉起全屏遮罩的路径必须有对应关闭 |
| ③n | 跳转 / 复制失败不能静默 |
| ③o | 音频实例必须挂 `onError` |
| ⑭ | 内容检查挂了建房仍能开（题卡仍拦） |

**这四类此前一条断言都没有** —— 因为它们管的是"失败时怎么办"，而我的断言全在查"成功路径对不对"。

### 顺带修的诊断能力

- 错误记录原来**看不出是哪个操作**（`act` 从 `opt` 取，而 action 在 `data` 里）
- 建房/进房失败只显示"开不了这一桌"，业务错误的具体原因被吞掉
- 进房失败只说"确认房间号"，没说"下一步该点什么"
