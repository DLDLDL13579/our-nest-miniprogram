# 调研：游戏手感（Game Feel / Juice）与酒桌游戏设计

> 2026-11-02 按用户要求「不要纯靠自己摸索，要调研、找方法」做的第一份调研。
> 来源都在文末。

## 一、Jackbox 的「The Jack Principles」——酒桌游戏的行业标杆

Jackbox 是派对/酒桌游戏的行业标杆（Quiplash / Drawful / Fibbage）。他们的设计文档叫
**The Jack Principles**，作者是创始人 Harry Gottlieb。

### 核心：做一台「互动对话界面」，而不是一个 App

> 设计师要让玩家产生**「有一个真人在主持、在带着你走」**的感觉。

这不是修饰。它决定了三件事：

**① 每次只让玩家做一件事**

> 游戏从不要求玩家在同一时刻做多个选择。永远是：选一个答案、画一张图、
> 或者输入一个词。

对照我的实现：大话骰同屏有「7 个叫法 + 开 + 劈 + 看规则」，
但那是**一件事的多个选项**（选叫法），不是多件事 —— 符合。

**② 赢是次要的**

> 玩 Jackbox 的时候，赢是次要的，真正的目标**是让这一群人笑出来**。

对照：我的结算页重点是「谁喝了几杯」，这是对的（酒桌的"输赢"就是喝酒）。
但**缺少"好笑"的瞬间** —— 比如大话骰开出一个离谱的结果时，没有任何"这事很荒唐"的表达。

**③ 降低门槛到"七十岁父母也能玩"**

对照：我的引导语（「从 3 个起叫」「按住盅偷看」）做得不错。

## 二、Game Feel / Juice 的三份经典材料

| 材料 | 作者 | 核心主张 |
|---|---|---|
| [The art of screenshake](https://www.youtube.com/watch?v=AJdEqssNZ-U) | Jan Willem Nijman (Vlambeer) | **屏幕震动是最廉价、最有效的打击感来源**；但幅度、频率、衰减都要调 |
| [Juice it or lose it](https://www.youtube.com/watch?v=Fy0aCDmgnxg) | Martin Jonasson & Petri Purho | 同一个游戏，加 20 个"多余的"细节（缩放、粒子、音效、缓动），体验天差地别 |
| [Squeezing more juice out of your game design](https://www.gameanalytics.com/blog/squeezing-more-juice-out-of-your-game-design) | GameAnalytics | **任何重要的元素都应该有动画**；一帧截图里能看出"每个 gameplay 元素都在动" |

### 可操作的清单（从这三份材料归纳）

1. **打击 = 位移 + 缩放 + 旋转 + 闪光 + 音效 + 震动**（缺一项就"软"）
2. **缓动曲线比时长重要**：同样的 200ms，线性 vs 回弹，手感完全不同
3. **过度动画不是错误**：缩放到 1.1 再回到 1.0，比直接到 1.0 有生命力
4. **屏幕震动要衰减**：开头猛、迅速收敛，而不是均速晃
5. **重要元素必须动**：静止的东西在玩家眼里就是"背景"

## 三、我的项目对照检查

### 已经做到的

| 项 | 状态 |
|---|---|
| 三通道错开（视觉→音效+30ms→震动+20ms） | ✓ 有 `feedback.js` 统一时间轴 |
| 逐颗粒化（骰子逐颗落定、转盘咔哒递减） | ✓ |
| 缓动曲线 | ✓ 大量 `cubic-bezier(.34, 1.4, .64, 1)`（回弹） |
| 过度动画（缩放 1.1 回 1.0） | ✓ 有 `dieDrop` `cupSlam` 等 |
| 屏幕震动 | ✓ 有 `bump()` / `.suspense` |
| 音效变体（避免听出循环） | ✓ 3 个骰子落定变体 + ±4% 音高抖动 |

### 还没做到的（这轮要补的）

| 缺口 | 依据 | 影响 |
|---|---|---|
| **结算缺少"荒唐感/笑点"** | Jack Principle ②「让这群人笑出来」 | 酒桌上最值得笑的是"开出离谱结果"，而我的结算只有陈述 |
| **缺少"主持人"的旁白质感** | Jack Principle ① | 我的提示语是系统口吻（「已扣盅，等其他人摇完」），不是"人"在说话 |
| **屏幕震动是否够猛** | Vlambeer | 需要实测：现在的 `bump()` 幅度够不够被感知 |
