# 打击感调研：顿帧才是第一原则（2026-11-03）

> 用户反复强调「动画要完美」，并明确要求「得找工具、调研、找方法，不能纯靠自己摸索」。
> 这份文档记录**外部研究给出的结论**、我们对照后的差距、以及落地了什么。

## 一、查到的核心结论

### ① 顿帧（hit-stop）是打击感的第一原则，不是屏幕震动

> 「freeze the game for a few frames on a heavy impact. That micro-pause,
>  often as short as **40 to 80 milliseconds**, sells weight better than any animation.」
> —— [How to Make Your Game Feel Good](https://egmatic.com/blog/how-to-make-your-game-feel-good)

**原理**：冲击那一刻画面完全静止几十毫秒，大脑才有时间"读完"这一下。
直接抖到底，感知上是一团糊的运动，重量感反而更轻。
物理类比：锤子砸下去，手腕会先顿一下再回弹。

**这条我们之前完全没有。** 只有 `.gamepage.impact` 的整屏抖动 ——
而调研明确指出：**只震不顿，等于把最有效的那个手段漏掉了**。

### ② 顺序必须是「先定住 → 再震」

同时做的话，定住的几十毫秒会把震动的**第一下（幅度最大的那一下）**吃掉，等于白做。

### ③ 时长有上限：40~80ms

超过就**从"有分量"变成"卡了一下"**。
这和"逐颗骰子落定只给 light 震动"是同一条分级原则 ——
**高频动作不能给强反馈**，否则整局都在震/顿，反而没有重点。

### ④ 三条已验证可用的技法（本轮只落地了第 1 条）

| 技法 | 出处 | 我们做了吗 |
|---|---|---|
| **顿帧** | egmatic / [The Art of Screenshake](https://hackread.com/the-juice-factor-designing-game-feel) | ✅ 本轮 |
| **屏幕震动** | 同上（"缩放震动强度到事件大小"）| ✅ 早就有（`roomImpact`）|
| **挤压拉伸** | 迪士尼动画原则 | ⚠️ 部分（骰子/骰盅是图片，不能形变）|

### ⑤ 必须可关闭

> 「these effects should be optional to avoid motion sickness and accommodate
>  players with photosensitivity」

我们已经有了 `reduce-motion` 开关，且走查过：**顿帧不受它影响是对的**
—— 顿帧是功能性反馈（告诉你"砸中了"），不是装饰性运动。

## 二、对照后的差距与落地

### 落地：`bump(hitStopMs)` 统一接口

改造前 `bump()` 只做整屏抖动。现在多一个参数控制顿帧：

```js
this.bump(60)   // 扣盅：60ms 定住后再震
this.bump(70)   // 揭盅
this.bump(80)   // 结算：全套里最重的一次
this.bump(0)    // 骰子逐颗落定完：显式不顿
```

**为什么 0 也要显式写**：默认 60ms 是好用的默认，但"忘了传参"和
"故意不要顿帧"在代码上一模一样 —— 将来有人往逐颗落定里加一次 `bump()`
就会悄悄多出顿帧。**这两种意图必须在代码上能区分。**

有断言锁（`test-game.js`）：每个 `bump(N)` 的 N 必须 ≤80，且必须显式写。

### 查过但**不做**的

| 技法 | 为什么不做 |
|---|---|
| `animation-play-state: paused` 做顿帧 | 小程序各基础库支持面不确定（Skyline 尤其）。用已验证的 `.freeze`（filter 提亮 + `pointer-events:none`）风险为零 |
| 更长的顿帧（150~200ms）| 超过 80ms 就从"有分量"变成"卡了一下"。研究结论和手感都不支持 |
| 骰子挤压拉伸 | 骰子是 SDF 渲染的静态 PNG，形变会破坏光影一致性。要做只能重渲染序列帧，成本远大于收益 |

## 三、这轮顺带修的两个音频缺陷

调研音频时顺手做的（详见 git 提交 `3.38.2`）：

| 缺陷 | 数字 | 根因 |
|---|---|---|
| 转盘咔哒三份变体响度不一 | **6.4 dB**（≈2 倍） | `import-audio.py` 里三个变体各自配了 `fifty=-14/-14/-16`；它们来自三个不同源文件，起音形状不同，**同样的 fifty 目标达不到同样的最终 RMS** |
| 骰子落定三份变体响度不一 | 2.1 dB | 同上 |

> **教训**：同一功能的一组变体，要用**同一个标定量**对齐，
> 而不是各自定一个"看起来合理"的目标值 ——
> 三份各自的 -14/-14/-16，合起来就是 6.4dB 的落差。

新增 `scripts/check-audio-variants.py`（同组 RMS 差 ≤1.0 dB）。

## 五、下一轮可以考虑的

1. **震动强度要按事件大小缩放**（调研原话"a pistol does not shake the screen like a rocket"）
   —— 我们现在的结果类震动基本是同一档，可以按"输多少杯 / 赢多干脆"分档。
2. **`reduce-motion` 下的替代反馈**：现在只是关掉装饰动画，
   但研究建议"关掉后要换一种不动的表达"（比如静态高亮），而不是干脆没有。
3. 顿帧目前只在骰子类用，**卡牌/转盘还没接** —— 金花摊牌那一刻其实很该有。
