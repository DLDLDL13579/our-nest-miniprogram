## 两条反复出现的教训

1. **截图会过期**。改过 mock 或布局后，旧图还在 `outputs/ui/` 里 ——
   看之前先重渲染，否则会去查一个已经不存在的问题。
2. **mock 的文案/数据是硬的，真机是算的**。截图只能证明"布局对不对"，
   不能证明"某个字对不对"。后者要回 `room.js` 查它是怎么算出来的。

## 一条给自己的提醒

**渲染器不是小程序**。它只跑 wxml + wxss，不模拟：
- 导航栏（用白底占位）
- tabBar
- 原生组件（input / picker 的外观）
- 任何 `wx.*` API 的真机行为

所以截图里**界面内容**可信，**外壳和原生控件**不可信。看到外壳不对，先查配置，别改样式。
