# 上线操作卡

> **一页纸。** 从上到下做完就能上线，不用翻别的文档。
> 详细说明在 [发布检查清单.md](发布检查清单.md)。

---

## ① 先改一个值（30 秒）

`miniprogram/config.js` 第 12 行附近：

```js
soloTest: true,     // ← 改成 false
```

**为什么**：`true` 时一个人也能开局（方便测试）。
正式版如果还是 `true`，**任何用户一个人就能开一局**，而酒桌游戏本该几个人玩。

⚠️ **这个开关历史上是你说"要留着测试"的，所以我没动。**
要上线就改它，还要继续测就留着。

---

## ② 跑一遍检查（2 分钟）

```bash
bash scripts/health.sh
```

**必须看到**：

```
① 版本：v3.11.14
② ✓ 全绿（388 项）
③ 主包 280KB / 分包 1936KB     ← 都要 < 2048
⑥ ✓ 5 份共享模块前后端一致
⑦ ✓ 响度层级 / 时间线重叠 全部达标
```

**任何一项红，停下来，别上传。**

---

## ③ 部署云函数（1 分钟）

**如果这次改过 `cloudfunctions/` 里的任何文件**：

```bash
R="$(pwd)"
/Applications/wechatwebdevtools.app/Contents/MacOS/cli cloud functions deploy \
  --project "$R" --env cloudbase-d4goh1zdtc8eb9708 \
  --names room --paths "$R/cloudfunctions/room" --remote-npm-install true
```

**验证它真的生效了**：

```bash
node .tooling/probe-room-cloud.js
# 必须看到：✓ 云端 room 与本地一致（指纹 + 字节数都吻合）
```

⚠️ **不部署 = 线上跑旧代码**，而本地一切正常。这是本项目踩过最大的坑。

---

## ④ 上传（1 分钟）

```bash
R="$(pwd)"
/Applications/wechatwebdevtools.app/Contents/MacOS/cli upload \
  --project "$R" -v 3.11.14 -d "上线版"
```

**然后用手机扫预览码玩一局**（`outputs/qr/` 里最新的那张）。

---

## ⑤ 微信后台填三项（10 分钟，只能你做）

| 项 | 位置 | 内容 |
|---|---|---|
| **服务类目** | 设置 → 基本设置 → 服务类目 | ⚠️ **选错不可改**，详见 [发布检查清单.md](发布检查清单.md) 的「类目怎么选」 |
| **用户隐私保护指引** | 设置 → 基本设置 | 照 [隐私指引-填写内容.md](隐私指引-填写内容.md) 抄，只需声明「收集你的昵称」 |
| **体验成员** | 成员管理 → 体验成员 | 加上要一起测的朋友 |

## ⑥ 提交审核 → 发布

审核通过后**发布**，才能生成**永久小程序码**。
（预览码有时效、只有开发者能扫，不能拿来推广。）

---

## 出问题了怎么办

| 现象 | 先查 |
|---|---|
| 点了没反应 | `node .tooling/probe.js --script cipline` |
| 提示「不认识的操作」 | **云端没部署**，回到第 ③ 步 |
| 界面哪里不对 | 对照 `docs/assets/screenshots/` 里的真机图 |
| 说不上来哪里不对 | 扫预览码，说出**具体哪个动作** |

---

## 一句话总结

**① 改 soloTest → ② health.sh 全绿 → ③ 部署云函数 → ④ 上传 → ⑤ 后台三项 → ⑥ 提交审核。**
