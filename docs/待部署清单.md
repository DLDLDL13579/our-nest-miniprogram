## 部署命令

```bash
# 一次只部署一个（CLI 的 --names 与 --paths 必须一一对应）
for fn in room; do
  /Applications/wechatwebdevtools.app/Contents/MacOS/cli cloud functions deploy \
    --project "$(pwd)" --env cloudbase-d4goh1zdtc8eb9708 \
    --names $fn --paths "$(pwd)/cloudfunctions/$fn" --remote-npm-install true
done
```

⚠️ **`cli cloud ...` 会自己拉起开发者工具的 Electron 进程**（AGENTS.md 实测过）。
   用户要求过不要在他电脑上起 GUI —— **部署前先问**，跑完 `cli quit` 并确认进程释放。

## 待决策：金花不记分（不是 bug，是设计缺口）

**现象**：结算页的「某某 今晚已经输了 N 局」用的是 `room.players[].score`，
而这个字段**只有大话骰在更新**（`calcDiceResult` 里 `score: (p.score||0) - 1`）。

| 玩法 | 有没有明确输家 | 记不记分 |
|---|---|---|
| 大话骰 | 有（输家喝） | ✓ |
| **梦幻金花** | **有**（比牌输的人出局） | **✗** |
| 谁是卧底 | 模糊（出局算不算输？） | ✗ |
| 比大小 | 有（输的人喝） | ✗ |
| 转盘 | 无（人人可能喝） | ✗ |

**所以**：玩金花/比大小时，那句"今晚输了 N 局"**永远不出现**；
而它恰恰是酒桌上最能带气氛的一句话。

**要不要补齐，取决于一个问题**：跨玩法的分数**该不该合并**？
- 合并：换玩法后"今晚输 5 局"继续累加 —— 更像"一晚上"的账
- 不合并：每个玩法独立 —— 但同一句话在不同玩法下含义不同

**我倾向不合并**（`score` 的语义是"这个玩法里输了几局"），
但那就该**按玩法分开存**（`scoreByGame: {liar: -3, poker: -1}`），
而不是现在这样"只有一个 score、只有大话骰在写"。

**改这个要动云端 + 前端 + 存档兼容，先记在这里，不擅自改。**
