## 待决策：金花不记分（不是 bug，是设计缺口）

**现象**：结算页的「某某 今晚已经输了 N 局」用的是 `room.players[].score`，
而这个字段**只有大话骰在更新**（`calcDiceResult` 里 `score: (p.score||0) - 1`）。

| 玩法 | 有没有明确输家 | 记不记分 |
|---|---|---|
| 大话骰 | 有（输家喝） | ✓ |
| **梦幻金花** | **有**（比牌输的人出局） | **✗** |
| 谁是卧底 | 模糊（出局算不算输？） | ✗ |
| 比大小 | 有（输的人喝） | ✗ |
| 转盘 | 无（人人可能喝） | ✗ |

**所以**：玩金花/比大小时，那句"今晚输了 N 局"**永远不出现**；
而它恰恰是酒桌上最能带气氛的一句话。

**要不要补齐，取决于一个问题**：跨玩法的分数**该不该合并**？
- 合并：换玩法后"今晚输 5 局"继续累加 —— 更像"一晚上"的账
- 不合并：每个玩法独立 —— 但同一句话在不同玩法下含义不同

**我倾向不合并**（`score` 的语义是"这个玩法里输了几局"），
但那就该**按玩法分开存**（`scoreByGame: {liar: -3, poker: -1}`），
而不是现在这样"只有一个 score、只有大话骰在写"。

**改这个要动云端 + 前端 + 存档兼容，先记在这里，不擅自改。**

## ⚠️ 更正：有些改动**不需要部署**就已经生效

之前这份清单笼统地说"5 个云函数改了什么"，但**其中一部分是前后端共享的纯函数** ——
前端 `require` 的是同一份代码，所以**扫码就能用**。

| 改动 | 在哪 | 不部署生效吗 |
|---|---|---|
| **不斋改斋可以减半** | `liarRules.canRaise`（前后端共享）| **✓ 生效**（前端生成选项时用它）|
| **叫骰选项按当前点数排序** | `liarRules.options`（同上）| **✓ 生效** |
| 起叫公式 | `liarRules.openNeed`（同上）| **✓ 生效** |
| **牌型名显示** | `dicerank` 在云端算 | ✗ 要部署 |
| **围骰/全围分级** | `liarCount` 在云端算 | ✗ 要部署 |
| **抽题去重** | `index.js` 的 `usedCards` | ✗ 要部署 |
| **单骰重摇** | `index.js` 的 `reroll` | ✗ 要部署（按钮已隐藏）|
| **卧底投票进度** | `index.js` 的 `iVoted` | ✗ 要部署 |

### 怎么判断"要不要部署"

**判据：这个逻辑跑在谁的机器上？**

  · 前端 `require('../../utils/xxx.js')` 并**自己算** → 共享模块 → **不部署也生效**
  · 前端只在 `call('room', ...)` 之后**读返回值** → 云端算 → **必须部署**

这条更正的意义：**之前我可能让用户以为"什么都没生效"**，
而实际上叫骰那半边（减半 + 排序 + 起叫）**已经在跑了**。

## ⚠️ 新发现：「今晚输了 N 局」只有比大小会显示

**`score` 只有一处更新**（`cloudfunctions/room/index.js:2146`，比大小的 `loserSeat`）。

而 `loserBoard`（结算页那句「倩萍 今晚已经输了 4 局」）依赖 `score <= -2`：

    room.loserBoard = ''
    if (room.phase === 'over') {
      const worst = players.filter(p => p.score <= -2).sort(...)[0]
      if (worst) room.loserBoard = worst.name + ' 今晚已经输了 N 局'
    }

**于是**：
  · **比大小** → 「输了 N 局」✓
  · **大话骰** → 永远不显示 ✗（而它是"输家最明确"的玩法）
  · 金花 / 卧底 / 转盘 → 也永远不显示

### 为什么这次没直接改

`score` 在云端维护，**改了也要部署才生效**（这份清单的前提）。
而"大话骰的写库位置"在 `index.js` 里散在几处（`open` 分支、`autoOpened` 分支），
**改错一处会让整局结算写坏** —— 不值得在"反正要等部署"的状态下抢这一个。

⚠️ 记在这里，**部署时一起做**：在 `open` 的两个分支里，给 `loserSeat` 那个人 `score - 1`。
