## 酒桌小程序：_.set 根因（史上最大 bug）
- ★ 酒桌小程序 2026-10-29 真根因：微信云开发 update 对**普通对象值**是深度合并（内部展开 $set:{'bid.face':1}），而房间文档 create 时把 bid/lastResult 初始化成 null → `Cannot create field 'face' in element {bid:null}` → 每房每局第一次叫骰/摇骰/转盘必挂，用户「从来没正常玩过」。修法：写库出口 cleanOpt 对普通对象/数组包 `_.set()`（不合并），命令对象原样，add 走 Insert 只清 undefined。
- 找到它的方法（用户要求「真实测试」后一轮）：automator 直调云端 + probeWrite 字段级实验。结果：turn/turnAt/updatedAt/players 回写 ok，bid/lastResult/streaks（对象）FAIL，bid=null ok → 判据清晰。脚本 .tooling/repro-bid.js 与 repro-all.js（29 步，覆盖 5 玩法的核心动作 + 再来一局 + 换玩法）。
- ★ 教训（比 bug 本身重要）：本地 mock 若不复刻真实数据库语义，那类 bug 永远测不出。mock 原来 d[k]=v 整体赋值 → 117 项断言全绿而线上必挂。现已实现深度合并 + null 报错，修复前跑测试确实红。**mock 的缺口就是测试的盲区。**
- 运行时事实：countdown→playing 由 status 轮询推进（云函数无定时器）；脚本里开局后必须先 status 再动作，否则「这局还没开始」。真实玩家 1.5 秒轮询感知不到。
