### 1.5.3 删掉三个鸡肋功能（2026-09-24 用户决定）

用户原话：「今晚吃啥，想你了，今天谁做饭，这三个功能有点鸡肋，可以删除」。

三个都是首页的「小工具」，删得很干净 —— 但**只有「想你了」牵动云端**：

| 功能 | 删掉的东西 | 云函数影响 |
|---|---|---|
| 今晚吃啥 | `spinFood` + `FOODS` + `.toolrow` 样式 | 无（纯前端随机） |
| 今天谁做饭 | `dice` + `diceResult` + `.duoc` 样式 | 无（纯前端随机） |
| **想你了** | `ping` + `PING_WORDS` + `.whisper` 徽标 | **`daily` 云函数 + `pings` 集合** |

**顺带拿到的性能收益**：`home` 聚合接口原本每次要多打两次 `pings` 计数查询
（我的 + 她的），删掉后首页少两次数据库往返。响应里也不再返回 `pingCount` / `partnerPing`。

**连带清理**（用户选择「连云端 daily 函数一起删」）：

- 删除云函数 `daily` 和 `answer`（前者只剩 `ping` 一个 action 活着，后者早已全废）
- 删除 `pings` 查询与 `db.command`（`home` 里 `_` 已无用途）
- `initdb` 集合清单从 10 个精简到 **5 个**：`pairs` `moments` `wishes` `capsules` `reminds`
  （去掉 `questions` `answers` `pings` `foods` 及从未使用的 `anniversaries`）
- `initdb` 里的 20 道种子题库一并删除（服务的是已废弃的「今日一题」）
- `config.js` 的 `fn` 映射去掉 `daily` / `answer`，补上漏掉的 `home`
- `app.js` 的 `DB_VERSION` 从 4 提到 **5** —— 否则已装设备不会重新走建库流程
- 测试：`mock-test.js` 原有 14 项断言全在已删的双盲机制上，**重写为 18 项**，
  覆盖配对 + 随手记 + 内容安全 + 越权 + 按天聚合这条真正在用的链路

> ⚠️ **云端还剩两个空函数**：`daily` 和 `answer`。微信开发者工具 CLI **没有删除云函数的命令**
> （只有 list / info / deploy / inc-deploy / download），只能在
> 云开发控制台 → 云函数 → 选中 → 删除。不删也不影响运行，只是留着占位。
> 同理 `questions` / `answers` / `pings` / `foods` 四张空表也要在控制台删。

### 1.5.2 修掉的五类问题（2026-09-24 体检）

这一轮没有加功能，全部是「本来该生效、实际没生效」的东西。共同点是**小程序不会报错**：
模板读到 `undefined` 只求值成假，页面照常渲染，只是悄悄走了另一条分支。

| # | 症状 | 根因 | 影响 |
|---|---|---|---|
| ① | 列表加载慢、流量大 | `home` / `chronicle` 漏返回 `thumbs` | **1.4.0 的提速优化等于白做** —— 前端回退加载原图，3~5MB/张 |
| ② | 编年史图片点不开 | 模板绑了 `previewPhoto`，js 里没这个方法 | 点击抛异常，无任何反馈 |
| ③ | 未配对页按钮点了没反应 | 模板绑的是 `goAnswer`（今日一题遗留名） | 死按钮 |
| ④ | 某天详情永远空白 | `day.wxml` 把数组当对象用（`d.partner.at`） | 详情页等于没用 |
| ⑤ | 「那年今日」多一条空行 | 模板渲染 `onThisDay.q`，随手记没有题干 | 界面脏 |

**① 是最值得说的**：`media.js` 花了很大力气做「上传时压一张缩略图、列表用小图、点开才加载原图」，
`write.js` 也确实把 `thumbs` 存进了数据库 —— 但两个列表接口忘了把这个字段带回来，
于是前端 `{{item.thumbs.length ? item.thumbs : item.photos}}` 永远走 `item.photos` 分支。
**机制做对了，接口漏了一个字段，整条优化就静默失效了。**

顺带修掉的：

- 首页 hero 在「已配对但还没填纪念日」时整块空白 —— 现在显式分支，引导去设置页
- `wishes` 点照片原本直接弹「撤销点亮？」对话框（破坏性操作绑在最易误触的区域），
  现在点照片看大图，撤销另给一个按钮
- 编年史的天标题原本没有任何入口能进详情页，`openDay` 和 `pages/chronicle/day/` 一直是死代码

### 1.5.2 的工程修复：derive.js 同步漏洞（**这条比上面所有 UI 问题都重要**）

`derive.js` 是「全 App 唯一的时间算法源」，云函数独立打包不能跨目录 require，所以每个用它的
云函数都留一份拷贝。**当时实际有 6 处**（prototype + miniprogram/utils + daily/home/chronicle/reminds），
但旧版 `scripts/sync-derive.sh` **硬编码了 2 条路径**，`check.sh` 也只校验这 2 处。

结果：`home` 和 `chronicle` 的拷贝长期停在旧版，**少了 `clampDay`** ——
那个函数正是为了修「每月 31 号在 9 月会静默进位成 10.01」而加的。

这两个云函数目前只调 `derive()`（不含月滚动），所以**还没炸**；但只要以后有人在 `home` 里
调一次 `nextMonthly`，就会拿到错误日期，而且没有任何测试会拦住它。

修法：`sync-derive.sh` 改成自动扫描 `cloudfunctions/*/derive.js`，以后新增云函数自动纳入。
现在 `check.sh` 会校验全部拷贝 —— 1.5.3 删掉 `daily` 后是 **5 处**，输出 `derive.js 5 处一致 ✓`。

### 1.5.2 新增的回归防线：`scripts/test-contract.js`

上面五类问题有一个共同点 —— **没有任何测试能发现它们**。原有的断言全在云函数业务逻辑里，
而这些都是「接口字段和模板对不上」。所以新增 9 项契约断言：

1. 列表接口必须返回 `thumbs`（`moments.list` / `home` / `chronicle` 三处，含老记录回退成 `[]`）
2. wxml 里 `bind*` / `catch*` 绑定的方法必须在同名 js 里真实存在
3. 模板引用的字段必须由云函数真实响应提供（幽灵字段检测）

**三条都做了反向验证**：故意把 `thumbs` 删掉、故意把 `goPair` 改回 `goAnswer`、
故意把 `{{onThisDay.q}}` 加回去 —— 测试确实各自报错，再恢复。不是摆设。

### 一条重要的产品决定：去掉了「每日一题」

原本的形态是每天推一道题、两人分开作答、都写完才解锁。**这个设计被否掉了**，理由是：

> 每日一问是热恋期产品的套路，靠制造新鲜感让人天天打开。
> 但在一起两年多以后，真正会让人打开小程序的时刻是「今天有件事想记下来」，
> 而不是「今天又有一道题要做」。
> 每天被问一个问题，三天后就会变成一条未读红点带来的愧疚感。

改成了 **随手记（moments）**：

- 没有"今天"的概念，没有连续打卡，没有补卡 —— 想记就记
- 写完她立刻能看见（不再双盲 —— 双盲是答题的规则，不是记录的规则）
- 一条也算数，不再要求"两个人都写了才显示"
- 一个人也能先用（不用等她加入才敢动笔）

### 1.5.1 新增两个功能（2026-09-23）

**① 时间胶囊** —— 写给未来的信

核心不是"能写信"，是**到期之前谁都打不开**：

- 未到期的信，云函数用 `field()` 明确**不查 text 字段** —— 正文根本没离开数据库
- 接口返回里 `text: null`，整个响应搜不到正文的任何一个字（有断言验证）
- 已到期的信不能删 —— 那是"已经寄出的信"，删了等于篡改历史
- 到期后可以回信，形成来回

> 和「双盲解锁」是同一套思路：把判断放服务端，前端只显示服务端允许它显示的东西。
> 常见错法是"内容发给前端 + CSS 遮罩"，那种锁抓个包就穿了。

**② 要记得的事** —— 生日 / 纪念日 / 还款

难点在两个地方：

- **提前量**：生日当天才提醒等于没提醒（那天你已经在饭桌上了）。
  每条带 `leadDays`，进窗口就标红说"该准备了"，而不是干巴巴一个数字。
- **日期滚动**：三种重复方式的边界各不相同，全部有断言覆盖：
  - 每年：`2/29` 在平年回落到 `2/28`，不能跳到 3/1
  - 每月：`31 号` 在小月落到月末（**这里抓到一个真 bug**：9 月会算成 10.01）
  - 一次：过了就是过了，不再滚动

还带一个「上次送了什么」字段 —— 解决连送三年同款的真实问题。

### 1.4.0 提速（用户反馈"加载慢、反应慢"）

**根因**：首页每次打开**串行**调 5 个云函数：

```
pair(status) → moments(list) → moments(stats) → chronicle(list) → daily
```

每次往返 200~600ms，串行相加 1~3 秒，而且 5 个函数各自可能冷启动。

**三层修法**：

| 层 | 做法 | 效果 |
|---|---|---|
| ① 聚合 | 新建 `home` 云函数，服务端内部 `Promise.all` 并发查完再一起返回 | **5 次往返 → 1 次** |
| ② 缓存 | 三个 tab 页加本地缓存：先用上次数据铺满界面，云端数据回来再静默替换 | 打开即见内容，不是白屏 |
| ③ 并发 | 编年史页的 list + stats 从串行改并发；其余页面同样处理 | 各页面少等一次往返 |

**一个细节**：缓存里的天数不能直接用 —— 它是昨天存的。
所以 `applyCache()` 会拿缓存里的 `anniversary` 在本地 `derive()` 重算一次天数，
保证即使走缓存，显示的也是**今天的真实天数**（实测跨零点后自动从 910 变成 911）。

### 1.3.0 修掉的五个问题（都是实际体验后发现的）

| 问题 | 根因 | 修法 |
|---|---|---|
| 没配对却显示"已完成配对" | `view()` 里没有"两人是否到齐"字段，前端拿 `myName` 判断 —— 而它永远有兜底值「我」 | 新增明确的 `paired` 布尔，前端只认它 |
| 刷新后邀请码消失 | 码只在 create 时返回，页面刷新后就没了 | `view()` 里带上 `inviteCode`（未配对时才给） |
| 图片尺寸参差不齐 | 直接用 `flex:1` 平分，原图比例不同就高矮不齐 | 统一固定高度 + `aspectFill` 裁切；单张时给大图 |
| 图片点不开 | 没绑预览事件 | 加 `wx.previewImage`，三处页面都支持 |
| 记录不能删 | 云函数有 remove 但界面没入口 | 长按卡片删除（只能删自己的，云函数二次校验）|
| 小工具要滑下去才能用 | 排在页面最底部 | 提到「记一笔」之后，首屏即可点击（实测 top=335px）|

**教训**：这五个里有三个不是逻辑错，是"界面上根本没有入口"或"用有兜底值的字段做状态判断"。
后者尤其典型 —— `myName` 永远有值，拿它当"已配对"的信号，就永远是已配对。

### 关于 `answers` 的唯一索引（1.5.3 已作废）

历史遗留：`answers` 是旧版「今日一题」的表，已被 `moments` 取代。

### 关于 bootstrap 这个函数

微信 CLI **没有调用云函数的命令**，`initdb` 只能人工去控制台点。为了让它能自动跑，
加了一个 `bootstrap` 云函数：云函数之间可以互相 `callFunction`，所以由它在云端替你调 `initdb`。
小程序启动时会先调 `bootstrap`，**跑完弹窗告诉你建了几个集合**。

## 二、第一次部署的 6 步（换 AppID 时才需要）

### 第 1 步：注册小程序，拿 AppID

1. 打开 <https://mp.weixin.qq.com> → 立即注册 → **小程序**
2. 主体类型选 **个人**（不需要营业执照）
3. 用一个**没注册过公众号/小程序**的邮箱
4. 注册完：登录后台 → 左侧「开发管理」→「开发设置」→ 复制 **AppID(小程序ID)**

> 个人主体能用的能力：云开发 ✅、内容安全接口 ✅、分享 ✅
> 个人主体**不能**用：微信支付 ❌（所以 v1 不做任何收费功能，这和之前说的一致）

### 第 2 步：装开发者工具

下载稳定版：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>

### 第 3 步：导入工程

1. 开发者工具 → 导入项目
2. **目录**选到 `情侣小程序/`（就是有 `project.config.json` 的这一层）
3. **AppID** 填第 1 步复制的那个
4. 后端服务选「**微信云开发**」
5. 导入后如果提示 AppID 不一致，点「确定」覆盖即可

### 第 4 步：开通云开发

1. 工具顶部点「**云开发**」按钮
2. 开通 → 环境名随便填（比如 `xiaowo`）→ 套餐选 **基础版 1**（免费额度足够两个人用）
3. 开通后左上角能看到**环境 ID**，形如 `xiaowo-3g8a1b2c3`
4. 把它填进 `miniprogram/config.js` 的 `env` 字段：

```js
module.exports = {
  env: 'xiaowo-3g8a1b2c3',   // ← 换成你的
  ...
}
```

> 只有一个环境时留空也能跑。填上更保险。

### 第 5 步：部署云函数

在工具左侧文件树里，**右键** `cloudfunctions` 下的每个目录 → 「**上传并部署：云端安装依赖**」。
或者用命令（改了哪个传哪个，`--remote-npm-install` 必须带，否则 `wx-server-sdk` 装不上）：

```bash
CLI=/Applications/wechatwebdevtools.app/Contents/MacOS/cli
for fn in pair moments home chronicle wishes capsule reminds initdb bootstrap; do
  $CLI cloud functions deploy --project "$(pwd)" --env <环境ID> \
    --names "$fn" --paths "$(pwd)/cloudfunctions/$fn" --remote-npm-install true
done
```

### 第 6 步：建库

云开发控制台 → 「云函数」→ `initdb` → 「测试」→ 参数留空 `{}` → 运行。
返回里会列出 11 个集合已创建、20 道题已灌入。

其实不用手工跑：小程序启动时会先调 `bootstrap`，由它在云端替你调 `initdb`。
`app.js` 里的 `DB_VERSION`（当前 `4`）控制这件事 —— **以后再加集合，只要把这个数加一**，
所有设备下次启动自动补建，不用教用户清缓存。

## 四、常见问题

**「云函数 pair 还没部署，或云环境不对」**
→ 第 5 步没做，或 `config.js` 里 `env` 填错了。

**数据都是空的**
→ 正常。云端集合建好了但都是 0 条 —— 这是干净状态，不是坏了。

**她扫不到 / 打不开**
→ 开发版只有**开发者本人 + 体验成员**能打开。后台「成员管理 → 体验成员」把她的微信加进去。

**想改在一起的日子**
→ 设置页改。全 App 只有这一个入口，改完所有数字自动跟着变。
